# Работа в DRIP Недвижимость

Это рабочее место аналитика недвижимости: Go backend, React/TypeScript frontend, PostgreSQL. Application содержит правила и порты, adapters связывают их с HTTP и хранилищем.

- Начни с существующей публичной операции и ее тестов.
- Источник HTTP-контракта - api/openapi.yaml. После изменения выполни `make generate PNPM=pnpm`: он обновляет Go и TypeScript. Generated-файлы вручную не редактируют.
- Реализация HTTP находится в backend/internal/adapters/httpapi. Используй имеющиеся сервисы application и обычный JSON-формат ошибок.
- Проверяй новую операцию через публичный NewHandler и новые тесты. Существующие тесты сохраняй.
- Во время этой небольшой задачи достаточно `cd backend && go test ./internal/adapters/httpapi ./internal/application -count=1` и генерации контрактов. Полную make verify-fast в агентском прогоне не запускай.
- Перед обычным релизом выполняются `make verify-fast`, `make e2e` и проверяется Validate в GitHub Actions. Production deployment не настроен.
- Правила хранятся в application, работа с SQL - в PostgreSQL adapter. Для новой операции сначала проверь существующие порты.
- Схема БД находится в backend/internal/adapters/postgres/migrations. Реальные данные не используй; тесты работают с синтетическими данными и подменами портов.
- Go форматируй gofmt. Не вводи зависимости без необходимости.
- В отчете разделяй выполненные проверки и непроверенное. Внешний проверяющий запускает полный набор отдельно.

Для маршрута изменения используй [карту репозитория](REPO_MAP.md). Значения показателей определены в [доменном словаре](CONTEXT.md). Сверяй документацию с кодом; отсутствие показателя не заменяй нулем.

Перед добавлением нового способа создания сессии прочитай [ADR о единых правилах создания](docs/adr/0001-session-creation.md) и проверь его по текущему application use case.
