# Практический семинар 5: Context Engineering

Три небольшие задачи в DRIP Недвижимость. В каждой паре меняются только файлы контекста; промпт, исходный код, модель и доступные инструменты фиксированы.

Материалы преподавателя, тесты evaluator и отчёты не входят в копию агента. Реальная БД не используется. Изменения агента остаются в отдельных временных репозиториях, а не переносятся в main.

## Запуск

Требуются Python 3.9+, Git, Go из `backend/go.mod`, Node.js 24.20.0, pnpm 11.25.0, Codex 0.160.1 с действующей авторизацией и Docker для независимой проверки SQL.

```sh
python3 seminar/run.py setup
make bootstrap PNPM=pnpm
docker build -t context-engineering-cli-grader -f seminar/fixtures/cli/Dockerfile seminar/fixtures/cli
docker pull postgres:18.6-bookworm
python3 seminar/check_context.py
python3 seminar/run.py run --example 01-http-contract
```

На машине с уже установленными инструментами можно задать `CE_PROMPTFOO_BIN`. `CE_TOOLCHAIN_BIN` задаёт каталог с закреплёнными node и pnpm. `CE_LOGIN_HOME` позволяет использовать существующую Codex-авторизацию; файл авторизации не копируется в Git.

Подготовка рабочих копий и зависимостей происходит до измерения. Каждый агент начинает новый диалог. Порядок повторов чередуется: до/после, после/до, до/после. Повторный запуск создаёт новый каталог отчёта и не удаляет предыдущий.

## Что сохраняется

- `prompt.txt` и SHA-256 промпта;
- исходный commit, отпечаток кода, файлы и объём контекста;
- разрешённые параметры модели и окружения;
- нативные JSON и HTML отчёты Promptfoo и консольный журнал;
- ответ, candidate.patch, логи независимых проверок и verification.json;
- входные, cached, uncached и выходные токены, время, raw-оценка API-эквивалента стоимости с неподтверждённым тарифом модели, команды;
- приватный сырой ответ Codex; папки `private` и `runtime` игнорируются Git.

Raw-отчёты остаются сохранёнными. Неисправный evaluator или сбой окружения помечаются отдельно от неудачного решения задачи. Исправленная оценка не переписывает исходный отчёт.

Три повтора - учебная демонстрация вариативности. Они не доказывают универсальное превосходство одной стратегии. Cached input входит в input и не прибавляется повторно; стоимость Promptfoo не является счётом по подписке ChatGPT.

## Последовательность

1. HTTP-контракт: описание проекта, AGENTS.md, команды, проверки и release.
2. Доменная задача: карта репозитория, архитектура и CONTEXT.md.
3. Команда БД: исторические учебные ADR и повторное использование решений.

Учебная ветка строится последовательными коммитами; `main` сохраняет чистый стартовый проект.

Чтобы открыть сохранённые серии на другой машине без вызовов модели, выполните `python3 seminar/run.py restore`. Команда импортирует official JSON в локальную базу Promptfoo и пропускает уже существующие ID, сохраняя пользовательские оценки. Авторизация Codex для этого не нужна.

Для нативного UI Promptfoo используйте тот же config directory, что harness: `PROMPTFOO_CONFIG_DIR=seminar/runtime/promptfoo-home seminar/runtime/tool/node_modules/.bin/promptfoo view --port 15501`. Открывайте http://127.0.0.1:15501/eval. Если использован CE_PROMPTFOO_BIN, вызовите этот бинарник вместо локального.

`official.json` фиксирует опубликованную серию для отчёта и аудита. `latest.json` указывает на последний локальный запуск, включая classroom; он не заменяет официальный результат.
