# Семинар 5. Самостоятельный проход от TBD до сравнения

Иди сверху вниз: здесь все команды, задания и тексты для файлов. На каждую задачу примерно 15-20 минут. Для группы: 10
минут вводной, по 20 минут на три задачи, 10 минут разбора.

В каждой паре промпт, код и модель одинаковые, меняются только документы. `compare` сам отправляет задание агенту через
Promptfoo. Вручную вставлять промпт в чат не нужно.

## 0. Подготовить пустые файлы

Если репозитория еще нет:

```sh
git clone --branch codex/context-engineering-seminar https://github.com/SinDenis/drip-real-estate-demo.git
cd drip-real-estate-demo
```

Далее все команды выполняй **из корня репозитория**. Нужны Python 3.9+, Git, Go 1.27, Node.js 24.20.0, pnpm 11.25.0,
Codex CLI 0.160.1 с авторизацией и работающий Docker. Если Codex еще не авторизован: `codex login`.

```sh
python3 seminar/run.py setup
make bootstrap PNPM=pnpm
docker build -t context-engineering-cli-grader -f seminar/tools/fixtures/cli/Dockerfile seminar/tools/fixtures/cli
docker pull postgres:18.6-bookworm
python3 seminar/run.py start
```

Открой в редакторе **`seminar/workspace`**. Это отдельная копия исходного проекта. Пять файлов контекста содержат только
`TBD`:

```text
seminar/workspace/
  AGENTS.md
  REPO_MAP.md
  CONTEXT.md
  docs/adr/0001-immutable-sessions.md
  docs/adr/0002-diagnostics-interface.md
```

Заполняй именно их. Корневые документы исходного репозитория и готовые снимки в `examples/` для прохода не нужны.
Остальные учебные файлы оставляй с TBD до своего шага. TBD не ломает запуск и не дает агенту содержательных правил.

Повторный `start` сохраняет твой текст. Для нового прохода: `start --workspace seminar/runtime/my-second-pass`, затем
тот же `--workspace` добавляй к `check` и `compare`.

`compare` переносит только документы текущего шага. Код всегда берется из `d037c2c`: изменения кода в учебной папке и
патчи предыдущих агентов в следующий запуск не попадают.

## 1. AGENTS.md: HTTP-контракт

**Задача:** добавить название сервиса в liveness, сохранив поведение API и оба контракта, Go и TypeScript. До запуска
запиши прогноз: какие действия изменятся после появления инструкций?

Одинаковый промпт для обоих вариантов уже сохранен в `examples/01-http-contract/prompt.txt`:

```text
В ответ GET /health/live добавь поле service со значением «DRIP Недвижимость». Сохрани существующее поле status, успешный HTTP-код и независимость liveness от доступности инфраструктуры. Другие HTTP-операции должны сохранить прежнее поведение. Реализуй изменение и проверь результат.

Работай только внутри выданного репозитория. Не меняй файлы контекста и существующие тесты, не создавай коммиты, не используй сеть и не обращайся к реальной БД. Допускаются новые тесты. В конце сообщи, что изменено, какие проверки действительно выполнены и что осталось непроверенным.
```

### Что написать

Замени TBD в **`seminar/workspace/AGENTS.md`**. Можешь сначала написать свой вариант и сравнить с этим:

```md
# Работа в DRIP Недвижимость

Рабочее место аналитика недвижимости: Go backend, React/TypeScript frontend, PostgreSQL. Application содержит правила и
порты; adapters переводят HTTP и SQL в эти правила.

- Сначала найди публичную границу изменения и существующие тесты.
- Источник HTTP-контракта - api/openapi.yaml. Generated Go и TypeScript не редактируй вручную.
- После изменения OpenAPI выполни make generate PNPM=pnpm: это обновляет обе стороны контракта.
- Для liveness выполни cd backend && go test ./internal/adapters/httpapi -count=1.
- Во время маленькой итерации выбирай узкую проверку поведения. Не ослабляй существующие тесты.
- Перед обычным релизом нужны make verify-fast, make e2e и зеленый Validate в GitHub Actions. Production deployment
  здесь не настроен.
- В учебном прогоне используй узкие проверки; Docker-проверки выполняет внешний evaluator. Не выдавай их за запущенные
  тобой.
- Application не импортирует HTTP и PostgreSQL adapters. Не добавляй зависимости без необходимости.
- Go форматируй gofmt, TypeScript и CSS - установленным Prettier.
- Реальные данные и БД не используй. Работай только в выданной копии.
- В конце перечисли изменения, фактически выполненные проверки и ограничения.
```

### Что вызвать

```sh
python3 seminar/run.py check
python3 seminar/run.py compare 1
```

Два вызова агента: **before** без инструкций репозитория и **after** с твоим AGENTS.md. Один повтор подходит для
знакомства; для трех повторов используй `compare 1 --repeats 3`.

После завершения AGENTS.md заморожен для следующего шага. Четыре остальных файла пока содержат TBD.

### Что посмотреть

Команда напечатает путь к новой папке отчета. Открой `summary.json`, затем `before-r1/verification.json`,
`after-r1/verification.json` и `candidate.patch` каждой строки. Правильный HTTP с устаревшим TypeScript-контрактом все
равно дает FAIL.

Сравни `total_tokens`, `uncached_input_tokens`, `latency_ms`, `trajectory.json`. Нашел ли агент генератор? Какие команды
выполнил? Инструкции не обязательно уменьшат расход. Для UI смотри шаг 4, его можно выполнить уже сейчас.

## 2. REPO_MAP.md и CONTEXT.md: показатель и его смысл

**Задача:** ответить на аналитический вопрос без изменения кода. Карта помогает найти источники, словарь отличает
накопительный показатель от продаж месяца.

Одинаковый промпт в `examples/02-domain-metrics/prompt.txt`:

```text
Для рабочего места аналитика оцени продажи за сентябрь по данным fixtures/ddu-snapshots.json. Укажи продажи месяца, известную сумму ДДУ в текущем срезе, полную сумму ДДУ по всем объектам, разность по сопоставимым парам и список объектов с недоступным текущим значением. Объясни ограничения и назови подходящие доменные термины. Не изменяй код и данные; верни ответ по предоставленной JSON-схеме.

Работай только внутри выданного репозитория. Не используй сеть, реальную БД, внешние отчёты и материалы преподавателя. Если показатель нельзя определить, используй null и объясни причину.
```

### Что написать

Замени TBD в **`seminar/workspace/REPO_MAP.md`**:

```md
# Карта репозитория DRIP

HTTP adapter вызывает application; application работает через порты; PostgreSQL adapter реализует хранение. Frontend
обращается к API через frontend/src/api. Не смешивай транспорт, правила и хранение.

| Хочу разобраться | Начать здесь | Проверить рядом |
|---|---|---|
| Изменить HTTP-ответ | [OpenAPI](api/openapi.yaml) | [HTTP adapter](backend/internal/adapters/httpapi), [API frontend](frontend/src/api) |
| Понять показатель | [Словарь](CONTEXT.md) | [Application](backend/internal/application), [ЕИСЖС adapter](backend/internal/adapters/eiszhs) |
| Проверить состояния и видимость сессий | [Миграции](backend/internal/adapters/postgres/migrations) | [Store](backend/internal/adapters/postgres/store.go), [Application](backend/internal/application/analytical_sessions.go) |
| Изменить локальную команду | [Makefile](Makefile) | [Тесты команд](tests/local_commands_test.sh) |

В учебную копию для аналитического вопроса добавляется fixtures/ddu-snapshots.json. Это синтетический срез.
```

Замени TBD в **`seminar/workspace/CONTEXT.md`**:

```md
# Язык аналитики недвижимости DRIP

**Текущий срез**: опубликованное состояние объекта на дату наблюдения. _Avoid_: список сделок месяца

**Накопительное количество ДДУ**: количество зарегистрированных ДДУ на дату среза. Оно не задает поток новых продаж за
месяц. _Avoid_: месячные продажи

**Разность накопительных показателей**: изменение между двумя доступными сопоставимыми значениями одного объекта. В нем
могут смешиваться регистрации, расторжения и корректировки. _Avoid_: точное число новых продаж

**Продажи месяца**: события продаж за календарный месяц. По двум накопительным срезам их количество не определяется.
_Avoid_: разность агрегатов ДДУ

**Недоступный показатель**: значение, которое не опубликовано или не получено. Это не наблюдение нуля. _Avoid_: нулевой
показатель

**Покрытие показателя**: состав объектов с доступными значениями. Сумма известной части не является полной суммой при
неполном покрытии. _Avoid_: весь рынок
```

В конец **AGENTS.md** добавь:

```md
- Для навигации используй [REPO_MAP.md](REPO_MAP.md), для терминов - [CONTEXT.md](CONTEXT.md).
- В аналитическом ответе различай накопительный показатель и события за период; неизвестное не заменяй нулем, известную
  часть не называй полной суммой.
```

### Что вызвать

```sh
python3 seminar/run.py check
python3 seminar/run.py compare 2
```

**Before** получает AGENTS.md, сохраненный в шаге 1. **After** получает текущий AGENTS.md, карту и словарь. Код снова
исходный, без HTTP-патча первого агента. Два ADR пока оставь с TBD.

### Что посмотреть

Ожидаются: известная сумма **175**, разность сопоставимых пар **0**, недоступный объект **9003**. Продажи месяца и
полная сумма неизвестны, поэтому **null**.

Прочитай объяснение, а не только PASS. В `trajectory.json` проверь, какие файлы агент прочитал. Файл на диске попадает в
контекст модели после загрузки harness или чтения инструментом. Обе версии могут ответить правильно: дополнительный
контекст не обязательно улучшает уже решаемую задачу.

## 3. ADR: новая команда БД и прежнее решение

**Задача:** добавить публичную команду. ADR объясняют, почему считаются видимые сессии и почему стоит использовать
существующий интерфейс подключения.

Одинаковый промпт в `examples/03-db-command/prompt.txt`:

```text
Добавь команду make session-stats для рабочего места аналитика. Она должна печатать CSV с заголовком total,active,complete,failed и одной строкой количеств аналитических сессий. Получай все счётчики одним SQL-запросом. Команда должна работать и на пустой базе, не изменять данные и сохранять существующие команды проекта. Реализуй и проверь результат.

Работай только внутри выданного репозитория. Не меняй файлы контекста и существующие тесты, не создавай коммиты, не используй сеть и не обращайся к реальной БД. Допускаются новые тесты. В конце сообщи, что изменено, какие проверки действительно выполнены и что осталось непроверенным.
```

### Что написать

Замени TBD в **`seminar/workspace/docs/adr/0001-immutable-sessions.md`**:

```md
# ADR 0001. Сессия как воспроизводимый срез

Статус: принято для учебной реконструкции. Это ретроспектива кода, не реальная история команды.

Сессия сохраняет неизменяемые фильтры анализа. Удаление скрывает ее из рабочего места, сохраняя происхождение анализа.
Поэтому статистика считает тот же видимый набор, что список сессий, а не все физические строки.

Видимость определяется отсутствием deleted_at. Active - queued и collecting; complete и failed учитываются отдельно.
Partial и canceled - самостоятельные состояния. Статуса deleted нет.

Источники: [схема](../../backend/internal/adapters/postgres/migrations/001_access.sql), [создание](../../backend/internal/adapters/postgres/migrations/003_analytical_session_creation.sql), [список сессий](../../backend/internal/adapters/postgres/store.go).
```

Замени TBD в **`seminar/workspace/docs/adr/0002-diagnostics-interface.md`**:

```md
# ADR 0002. Диагностика через существующий интерфейс

Статус: принято для учебного примера. Причины реконструированы по коду; единый срез - учебное решение.

В проекте уже есть db-query и подменяемый DOCKER. Переиспользуем этот интерфейс: отдельное подключение в каждой команде
создает расходящиеся настройки и способы экранирования.

Счетчики получаем одним SELECT без изменения данных, чтобы они относились к согласованному срезу. Пустой набор дает
нули. Публичный stdout содержит только заявленный формат, без recipe echo и служебных сообщений. Учитывай пути с
пробелами и stdout вложенного make.

Сам db-query допускает произвольный SQL и не гарантирует read-only. Это подтверждает отдельная проверка с правами SELECT
на синтетической БД.

Источники: [Makefile](../../Makefile), [контракт команд](../../tests/local_commands_test.sh).
```

В конец **AGENTS.md** добавь:

```md
- Перед изменением диагностики прочитай [ADR 0001](docs/adr/0001-immutable-sessions.md)
  и [ADR 0002](docs/adr/0002-diagnostics-interface.md). Проверь их применимость по текущей схеме и командам.
```

### Что вызвать

```sh
python3 seminar/run.py check
python3 seminar/run.py compare 3
```

**Before** получает контекст, сохраненный в шаге 2. **After** получает текущие документы и ADR. Внешний evaluator
исполняет SQL в отдельной временной PostgreSQL, пользовательский volume не используется.

### Что посмотреть

В `verification.json` проверь счетчики, исключение скрытых сессий, пустую базу, один запрос, чистый CSV, отсутствие
записи и прежние команды. В `candidate.patch` найди, использован ли `db-query` или создано еще одно подключение.

Правильные числа и соблюдение архитектурного решения - разные критерии. Не объявляй архитектурное наблюдение новым
критерием PASS после просмотра результата.

## 4. Посмотреть логи в Promptfoo

Можно выполнить после любого шага. В отдельном терминале:

```sh
python3 seminar/run.py view
```

Открой [Promptfoo](http://127.0.0.1:15501/eval?mode=all). Если сервер уже работает, команда вернет ссылку. Если
запускает новый, оставь терминал работающим. Для другого порта: `view --port 15502`.

В истории выбери свежую серию по названию задачи и времени. У нее строки **before**, **after** и номера повторов.
Посмотри:

1. **Failures**: какая независимая проверка провалилась.
2. **View output**: ответ агента и результат проверяющего.
3. `promptfooconfig.json`: `prompts` задает вход, `providers` запускает Codex, `tests` задает копии, `assert` вызывает
   проверяющий.
4. `trajectory.json` и `candidate.patch`: действия и изменения.
5. `summary.json`: качество, время и токены каждой строки. Общий PASS в шапке смешивает оба условия.

Каждый `compare` создает **`seminar/reports/<задача>/<время>/`** и печатает путь. `latest.json` указывает последний
запуск; `official.json` указывает прежнюю записанную серию. Старые отчеты не перезаписываются.

## 5. Завершить проход

У тебя пять заполненных документов и три сравнения. Для каждого запиши: что ожидал, что произошло, чем это
подтверждается, что убрать или уточнить в контексте.

Проверь контекст на трех уровнях:

- **Технический**: `check` проверяет ссылки, команды Make и бюджет AGENTS.md. `pending_context_files` показывает TBD.
  PASS не подтверждает смысл текста.
- **Смысловой**: термины и решения согласованы со схемой, кодом и пользовательским поведением. Например, deleted не
  является статусом сессии.
- **Практический**: одинаковое задание, независимые проверки и действия агента. Правильный документ может не помочь
  конкретной задаче.

`total_tokens` - расход всего цикла, не размер окна. Cached input входит в input;
`uncached_input_tokens = input_tokens - cached_input_tokens`. Для одного запроса смотри
`largest_observed_request_input_tokens`. Цена в UI для этой модели не проверена, не используй ее как доказательство
экономии.

Один повтор показывает механизм. Даже три не доказывают статистическое превосходство. Сравниваются пакеты документов, не
вклад каждого файла отдельно. Go/npm и серверный prompt cache между попытками не сбрасываются. Invalid trial из-за
provider или evaluator не является ошибкой решения; исправь окружение и повтори шаг.

### Пройти по готовым результатам без вызова модели

```sh
python3 seminar/run.py restore
python3 seminar/run.py view
```

В прежней серии 18 попыток: HTTP **1/3 -> 3/3**, аналитика **3/3 -> 3/3**, БД **3/3 -> 3/3**. В дополнительном разборе
БД переиспользование `db-query` было **1/3 -> 3/3**, это наблюдение после запуска вне первоначального PASS.

Старые результаты получены с прежними подробными документами, они не являются результатами твоих пяти
файлов. [Сохраненный разбор](reports/RESULTS.md). Первый HTTP pilot имел ошибку evaluator и не входит в основное
сравнение. Ошибочная ранняя заметка со статусом deleted сохранена; для третьей задачи она была исправлена.

Готовая история: `d037c2c` (чистый код), `e67ab5c` (инструкции), `129d47d` (карта и словарь), `db4ae51` (ADR), `c2bfa1c`
(импорт и разбор). Для этого самостоятельного прохода переключать коммиты не требуется.
