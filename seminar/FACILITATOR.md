# Памятка преподавателя

## До занятия

Откройте [сценарий на 80 минут](SEMINAR.md), [рабочий лист](WORKSHEETS.md), интерактивный отчёт в `.lavish/seminar-5.html` и нативные HTML Promptfoo из reports. Записанные результаты обязательны как резерв: живой прогон зависит от подключения к модели и доступного лимита.

Проверьте Codex login, версии из README и Docker. Для SQL-проверки заранее соберите образ и загрузите PostgreSQL; для HTTP подготовьте frontend dependencies:

```sh
python3 seminar/run.py setup
python3 seminar/run.py restore
make bootstrap PNPM=pnpm
docker build -t context-engineering-cli-grader -f seminar/fixtures/cli/Dockerfile seminar/fixtures/cli
docker pull postgres:18.6-bookworm
python3 seminar/check_context.py
python3 seminar/check_reports.py
```

Подготовка и загрузка образов выполняются до замера. В Promptfoo выключен его response cache, но серверный cached input модели и Go/npm cache остаются. Порядок чередуется, а не случайно перемешивается; это учебная серия, не строгий статистический эксперимент.

Не запускайте dev-up и не монтируйте реальный PostgreSQL volume в evaluator. Для трёх задач достаточно кода и synthetic fixtures. Цена из Promptfoo сохраняется как raw-оценка; тариф gpt-6.1-sol проверяющим не подтверждён, для сравнения используем токены и время.

## Начало: 0-10 минут

Покажите main без файлов контекста и учебную ветку с тремя последовательными коммитами. Код для всех задач архивируется из одного d037c2c; результаты одного агента не являются входом следующего. Каждый коммит хранит отдельный пример, его документацию, патчи и отчёты.

Попросите группы написать прогноз до просмотра ответов: какая ошибка вероятна и какая информация может её предотвратить? Зафиксируйте критерий отдельно от самопроверки агента.

Объясните, что модель получает инструкции harness, задачу, автоматически найденный AGENTS.md и прочитанные инструментариями сведения. REPO_MAP.md, CONTEXT.md и ADR не обладают специальной магией имени. Навигация делает их обнаружимыми, но прочитать и применить их ещё нужно.

## Пример 1: 10-30 минут

Сначала покажите только [фиксированный промпт](examples/01-http-contract/prompt.txt). За 5 минут группы предлагают не больше 20 строк AGENTS.md: источник контрактов, соглашения и узкие команды проверки. Обсудите, чем итерация отличается от release.

Покажите сохранённые before/after и HTTP-проверку через публичный handler с недоступной инфраструктурой. Успех требует поведения liveness, прежнего readiness, текущих Go/TypeScript контрактов и прохождения существующих HTTP-тестов. Нельзя объявлять успех только по словам агента.

Результат серии: before 1/3, after 3/3. Откройте before-r2 или before-r3: устаревший frontend schema при рабочем Go API. Откройте один after: генерация двух контрактов и узкая проверка. Разберите калибровку отдельно: ошибку evaluator нельзя засчитывать модели, широкая обязанность запускать все проверки может удорожать простую задачу.

## Пример 2: 30-50 минут

Дайте группам [срезы ДДУ](examples/02-domain-metrics/fixtures/ddu-snapshots.json) и [тот же промпт](examples/02-domain-metrics/prompt.txt). За 5 минут попросите распределить факты между картой, архитектурой и словарём. В словаре должны быть определения, не команды и имена таблиц.

Ключ разбора: известная текущая сумма 175; сопоставимая разность 0; месячные продажи и полная текущая сумма неизвестны; объект 9003 имеет недоступное значение. Вычитать можно сопоставимые значения, но назвать результат продажами нельзя.

Обе версии дали 3/3. Карта и словарь не дали наблюдаемого выигрыша в точности; медианные суммарные токены выросли. Обсудите, достаточно ли fixture, исходного кода и знаний модели для этого вопроса. Для отдельной проверки пользы карты и словаря нужны ablation-условия; текущая пара проверяет весь пакет.

Обязательное упражнение проверки документации: в сохранённом v1 architecture.md ошибочно описан deleted как статус. Попросите сверить это с migration 001_access.sql и запросом списка сессий. Правильно: deleted_at отдельно, canceled входит в enum. Доменный evaluator не тестировал это утверждение и его пропустил. Исправленный snapshot отмечен v2-schema-correction и используется только в следующем примере; прежние результаты не переписаны.

## Пример 3: 50-70 минут

Покажите [фиксированный промпт команды](examples/03-db-command/prompt.txt). Группы формулируют контракт: один SELECT; тот же видимый набор, что UI; active = queued/collecting; partial/canceled самостоятельны; нули на пустой базе; stdout ровно CSV; DOCKER может быть путём с пробелами.

Сравните [ADR 0001](../docs/adr/0001-immutable-sessions.md) и [ADR 0002](../docs/adr/0002-diagnostics-interface.md). Это явно подписанные учебные реконструкции по коду, а не выдуманные записи реальной команды. Причина решения должна помогать новой задаче; готовый SQL-патч в ADR не нужен.

Независимый проверяющий захватывает SQL команды с подменённым Docker, выполняет его в временной PostgreSQL ролью с SELECT и запрещённой записью, проверяет mixed/empty/partial-and-deleted fixtures, чистый CSV и сохранность существующих локальных команд. Агент не имеет Docker или доступа к реальным данным.

В опубликованной серии обе версии прошли 3/3; медианная разница total составила только 2,6%, времени 1,7%. ADR не дал наблюдаемого выигрыша в точности. По патчам есть конкретный архитектурный выбор: db-query переиспользован в 1/3 baseline и 3/3 guided; два baseline дублируют psql-флаги. Сравните before-r2 и after-r2 и объясните, где теперь меняются параметры подключения. Это дополнительное наблюдение после запуска; оно не меняет основной pass и не является статистическим доказательством. Само чтение документа не доказывает улучшение.

## Совместное проектирование и живой прогон

Для редактирования используйте отдельную копию, не меняя сохранённые snapshots:

```sh
python3 seminar/run.py prepare --example 01-http-contract
python3 seminar/check_context.py seminar/runtime/classroom/01-http-contract
python3 seminar/run.py run --example 01-http-contract --after-source seminar/runtime/classroom/01-http-contract --revision classroom-a --repeats 1
```

После prepare группы меняют только файлы контекста в classroom-копии и запускают checker снова. Code changes из classroom не включаются в эксперимент: код по-прежнему берётся из зафиксированного базового commit. Для следующего изменения выбирайте новое имя revision: старое сохраняется. Один повтор годится для живого разбора, но не сравнивайте его как равную по надёжности серию с тремя повторами.

Обычный повтор сохранённого опыта: `python3 seminar/run.py run --example 03-db-command`. Он использует уже замороженные документы, создаёт новый отчёт и не заменяет предыдущий. Последний набор становится latest; прежние каталоги остаются. Официальные серии закреплены отдельным official.json и не заменяются classroom-прогоном.

## Завершение: 70-80 минут

Покажите три разных измерения: общий расход за задачу, uncached часть input и самый большой наблюдённый input одного запроса. Общая сумма не является размером контекстного окна. История и outputs tools попадают в следующие запросы; компактный поиск, релевантные фрагменты и узкие проверки уменьшают лишний контент. Cache уменьшает повторную обработку, но cached сведения продолжают занимать место в запросе.

Каждая группа сдаёт один AGENTS.md, 3 маршрута карты, 4-6 терминов, короткий ADR и критерий полезности. Оцените по источникам, применимости, актуальности, достаточности, непротиворечивости и независимому поведению. Автоматический checker проверяет ссылки, команды и бюджет; смысл проверяют по коду и данным, а не наличию заголовков.
