# Методика и границы вывода

## Что сравниваем

В каждой задаче один prompt.txt, одна версия кода d037c2c, gpt-6.1-sol с reasoning low, одинаковые доступные инструменты и одинаковый режим sandbox. Различается пакет файлов контекста. У каждой задачи две версии и три независимых диалога. Порядок: before/after, after/before, before/after.

Первый пример сравнивает пустой repository context с описанием, workflow и AGENTS.md. Второй добавляет карту, архитектуру и доменный словарь к базовым инструкциям. Третий добавляет два ADR и ссылки на них к исправленному полному контексту второго примера. Последовательность коммитов является последовательностью учебных материалов; код приложения и результаты предыдущих агентов не накапливаются между задачами.

Это сравнение пакетов, а не отдельное измерение AGENTS.md против REPO_MAP.md или CONTEXT.md. Для причинного утверждения о конкретном файле нужны дополнительные ablation-условия. Учебных трёх повторов недостаточно для статистического превосходства стратегии или обобщения на другие задачи и модели.

## Изоляция

Каждый агент работает в новом Git-репозитории с фиксированным кодом и замороженными документами. Teacher harness, отчёты и evaluator не экспортируются. Авторизация остаётся в игнорируемом runtime, не входит в Git. Для аналитической задачи sandbox read-only; для изменений - workspace-write. Сетевой поиск и сеть инструментов отключены; связь harness с моделью нужна для самого inference.

Go/npm caches общие, серверный prompt cache не сбрасывается. Подготовка рабочей копии и frontend dependencies происходит до provider latency. Измеренное время - выполнение provider, включая его цикл инструментов, а не полный startup занятия или сумма времени независимых grader-проверок.

## Проверка результата

Успех определяется конъюнкцией проверок, не средним баллом и не финальной репликой агента. Score помогает найти частично верное решение, но строки со score < 1 не считаются успешными.

1. HTTP: публичный handler, liveness при недоступном readiness probe, прежний readiness, актуальность обоих generated контрактов и существующие HTTP-тесты. Дополнительно проверяется неизменность исходных тестов.
2. ДДУ: числовые литералы и неизвестные значения независимого oracle, покрытие, missing ID, наличие терминов и объяснения, неизменность репозитория. Семантическая полнота свободного объяснения не доказывается проверкой его длины; ответы просмотрены отдельно.
3. БД: SQL извлекается через подмену CLI, реально исполняется в временной PostgreSQL 18.6 с SELECT-only ролью и read-only настройкой. Fixtures согласованы с enum и deleted_at продуктовой миграции. Проверяются видимый набор, разные состояния, пустая база, один вызов SQL, пути с пробелами, чистый CSV, сохранность данных и существующих локальных команд.

Для всех строк сохранены candidate.patch до любых действий grader, input.json, ответ, логи и verification.json. Проверяются отпечатки файлов контекста после работы. Проверяющий каждой основной серии сохранён рядом с её отчётом; старые результаты не оцениваются молча новой версией.

## Токены и окно

Input - суммарные входные токены за все запросы agent turn. Cached input является частью input; uncached = input - cached. Total = input + output. Повторное включение истории и outputs tools увеличивает общую сумму. Самый большой наблюдённый input отдельного запроса и последний input берутся из Codex rollout и сохраняются отдельно.

Ни total, ни сумма input не является размером контекстного окна. Даже observed request input не измеряет будущую вместимость или качество внимания модели. Модель может сокращать историю; в этой серии сравниваем фактические наблюдения, не заявляем эксперимент с пределом окна. Cache не удаляет сведения из запроса.

Promptfoo сообщает raw-оценку стоимости, но предупреждает, что модель неизвестна его каталогу. Тариф gpt-6.1-sol не валидирован. Оценка не является счётом подписки ChatGPT и не используется как доказательство экономии.

## Калибровка и исправления

Первый HTTP pilot имел ошибку evaluator: новый тест модели принимался за изменённый исходный тест. Оригинальные отчёты сохранены и отмечены invalid comparison. Исправленная regrade без повторного inference хранится отдельно. Официальная серия запущена после исправления, с более узкими инструкциями итерации.

В architecture.md второй серии ошибочно появился статус deleted. Доменный grader проверял ДДУ и не обнаружил эту ошибку. Сохранённые v1 документы не переписаны; v2-schema-correction содержит исправление, служащее входом третьей задачи. Ранняя калибровка БД с таким же ошибочным enum отмечена непригодной для продуктовой схемы. Исправленный grader проходит положительный пример и отклоняет две заранее внесённые ошибки.

Автоматический check_context.py проверяет ссылки, существование команд и выбранный byte budget AGENTS.md. Он не подтверждает правдивость текста. Проверка по схемам, публичному поведению и данным обязательна. Не превращайте зелёный checker в утверждение, что весь контекст корректен.
