# Архитектура и данные

Документ объясняет технические границы. Значения бизнес-слов находятся в [CONTEXT.md](../CONTEXT.md), навигация - в [REPO_MAP.md](../REPO_MAP.md).

## Слои

- `application` принимает решения о сессиях, доступе, выборе источников и получении данных; зависимость от внешнего I/O описывается портами.
- `adapters/httpapi` работает со strict OpenAPI DTO. `adapters/postgres`, `eiszhs` и `objectstorage` обеспечивают внешнее I/O.
- `platform/bootstrap` связывает зависимости; `cmd/api` - точка запуска.
- Frontend обращается к API только через `src/api`. Runtime содержит API и собранные UI-ресурсы.

## Сессии и показатели

`analytical_session` хранит сохранённый выбор и состояние. Состояния `queued` и `collecting` активны; `complete`, `partial`, `failed`, `canceled` самостоятельны. Удаление хранится отдельно в `deleted_at`, не в статусе. Список видимых сессий выбирает `deleted_at IS NULL`.

Фильтры и привязка наблюдений сохраняют воспроизводимость анализа. Миграция блокирует изменение фильтров сохранённой сессии. Повтор создания с тем же Idempotency-Key воспроизводит результат; другой запрос под тем же ключом конфликтует.

Показатели ЕИСЖС в current collection - опубликованные накопительные значения. Отсутствующее значение отображается как недоступное; API может не содержать `cumulativeDduCount`. Разность состояний не является потоком новых сделок. Это доменный смысл, а не свойство формулы вычитания.

## Проверка границ

HTTP проверяется через публичный handler, UI через DOM и HTTP seam, диагностическая команда через CLI и read-only SQL. Для влияющих на PostgreSQL или S3 изменений нужен отдельный контейнерный E2E. Учебный evaluator использует только синтетические fixtures.

Источник: application, postgres migrations, HTTP DTO, UI и executable architecture tests базового коммита `d037c2c`.
