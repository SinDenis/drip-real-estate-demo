# ADR 0002: Диагностика через существующий интерфейс Make

Статус: принято для учебного примера. Ретроспектива опирается на существующие команды; правило единого среза является учебным решением, а не установленным фактом истории команды.

## Контекст

В проекте уже есть Makefile, Compose и db-query. Тесты локальных команд подменяют DOCKER, включая путь с пробелами, и проверяют передачу SQL без интерпретации shell. Если каждая диагностика создаёт собственный способ подключения, настройки и ошибки начинают расходиться.

## Решение

Расширять текущий диагностический интерфейс, сохраняя DOCKER и Compose как точки подмены. Диагностические счётчики получают одним SELECT, без изменения данных. Отдельный вывод для автоматического потребителя содержит только заявленный формат: recipe echo и служебные сообщения туда не входят. Использование вложенной команды должно учитывать её фактический stdout.

## Причина и последствия

Один запрос даёт согласованный срез и естественные нули для пустого набора. Единый способ подключения сохраняет локальные соглашения и позволяет проверять команду без реальной БД. Экранирование путей и чистота stdout являются частью публичного контракта. Существующий db-query принимает произвольный SQL; сам по себе он не гарантирует read-only. Независимая проверка запускает SQL с правами SELECT и запрещённой записью.

Источники: [Makefile](../../Makefile), [контракт команд](../../tests/local_commands_test.sh), [workflow](../development.md). Учебная проверка использует отдельную синтетическую PostgreSQL, не пользовательский volume.
