# ADR 0001. Единые правила создания неизменяемой сессии

Статус: принято для учебной реконструкции по существующему коду. Это сгенерированная ретроспектива, не документ реальной истории команды.

Сохраненная сессия фиксирует выборку и происхождение анализа. Копирование строки БД переносит устаревшие наблюдения, автора и состояние. Отдельные способы создания также начинают по-разному нормализовать фильтры и обрабатывать повторы.

Решение: каждый способ создания передает канонические идентификаторы фильтров в единый application use case создания. Он заново определяет автора, время, идентификатор, название, состояние и доступные свежие наблюдения. Результат старой сессии не является результатом нового анализа. Исходная сессия остается неизменной.

Идемпотентность принадлежит логической операции создания: сотрудник, область операции и ключ связываются с хэшем канонических фильтров. Повтор возвращает прежний результат, несовпадающие фильтры дают конфликт. Не создавай второй механизм идемпотентности рядом с существующим.

Последствие: новая точка входа переиспользует правила, проверки доступа и порты. Прямое клонирование записи или повторение SQL и нормализации в HTTP adapter нарушает это решение.
